# Spatial index benchmark

Generated by `python -m scripts.benchmark_spatial_index` on 2026-10-12.

**Query:** how many people live within 1 mile of a point, over the 38,180 census blocks:

```sql
SELECT count(*) AS blocks, sum(population) AS people
FROM census_blocks
WHERE ST_DWithin(center::geography, ST_SetSRID(ST_MakePoint(:lng, :lat), 4326)::geography, :radius)
```

**Method:** 20 points across Dallas County, 5 timed runs each (after one
warm-up), using `EXPLAIN ANALYZE`'s execution time (time inside Postgres only). "Without index"
drops `ix_census_blocks_geography` inside a transaction that is rolled back afterwards.

| | Median | Slowest | How Postgres read the table |
| --- | --- | --- | --- |
| With index | 0.28 ms | 0.61 ms | Bitmap Heap Scan, Bitmap Index Scan |
| Without index | 33.11 ms | 38.87 ms | Seq Scan |

**The index makes this query about 119x faster.** Without it, Postgres reads all 38,180
blocks and measures the distance to each one (a sequential scan). With it, Postgres walks the
GIST index's tree of bounding boxes to find only the blocks near the point, then measures just
those.

Example: within 1 mile of (32.8167, -96.7572) there are 320 census blocks with
19,140 people.
